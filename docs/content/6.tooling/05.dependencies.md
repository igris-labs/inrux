The dependency refresh on November 20, 2026 updates Inrux's direct dependencies to current stable releases, except the documentation TypeScript compiler. A feature-alignment dependency on Naga 26 follows the current Masonry/Vello shader graph; independently upgrading that declaration to Naga 30 would not update the engine and would break shader diagnostic compilation. The Cargo, pnpm and npm lockfiles record the resolved graphs. Use locked/frozen installs to reproduce a checkout.

A newer version alone does not demonstrate a performance improvement in Inrux.

## Migration details

The egui host uses the current `App::ui` lifecycle. Native editor bridges use the updated IME preedit and font metadata APIs. Clipboard support is enabled explicitly because eframe now makes it optional.

The Taffy callback now receives `LayoutInput` and produces `LayoutOutput` through `compute_leaf_layout`. The bridge uses the current overflow rectangle and alignment types. Taffy IDs and types stay private.

Inrux's Masonry editor bridge uses Parley 0.13 directly, with its own layout context. The published Masonry backend still depends on Parley 0.6 internally. Inrux does not force incompatible versions into upstream code. Accessible text runs and selection mapping now belong to the adapter because current Parley no longer supplies the older AccessKit helper API.

The extension uses TypeScript's Node16 module resolution and a logging output channel required by the current language client. The docs remain on TypeScript 6: the installed Vue checker uses the JavaScript compiler API, which TypeScript 7 does not provide. No compatibility shim or disabled type check is used. Nuxt Content is aligned to one version across the site and its layer so generated collection types refer to the same package.

Local `block` and `proc-macro-error2` source patches remain necessary until fixed upstream releases are published. See [third-party notices](/tooling/license).

## Requirements and checks

The workspace declares Rust 1.98, which the current source APIs require; eframe 0.37 itself requires Rust 1.95. Use current stable for the lockfile. Declaring that floor does not certify the complete graph on Rust 1.98; the minimum-version build still needs its own validation.

After dependency changes, run workspace tests, strict Clippy, formatting, backend isolation checks, example compilation, extension checks and the documentation build. Engine internals can retain older transitive dependencies where their upstream APIs require them. Do not force a transitive major upgrade merely to reduce duplicate versions.
